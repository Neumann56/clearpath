# AI 助手「老周」接入说明

> 角色定位：外贸业务经理，不是客服。坐在用户旁边帮他判断要不要接单、钱够不够、货能不能进。
> 代码：`public/js/assistant.js`（交互与调用）、`public/js/assistant-prompt.js`（人格与上下文）

---

## 一、它只做六件事

**入口统一在右下角**：一个带「周」字头像和「问老周 / 外贸 12 年」的悬浮按钮，除了打印页和后台参数页，每个页面都有。

| 场景 | 模式 | 做什么 |
| --- | --- | --- |
| 报告页 | `report` | 解释报告里的数：关税怎么来的、现金缺口为什么这么大、232 会不会落到这票上、要准备什么资料 |
| 录入页 | `form` | 把客户的原话翻译成表单字段，并回填、触发校验 |
| 录入页（发图） | `form` | 读发票、装箱单、报关单、询价截图，把能确定的字段填上，每个字段附图上原话（见第七节） |
| 其余所有页面（首页 / 历史报告 / 政策日历 / 批量 / 待核 / 准确率） | `general` | 讲这套工具怎么用、概念怎么理解、什么样的单子容易算不准 |
| 同上（问到外贸本身时） | `general` | 答成交顺序、报价单、付款方式、单据、术语、常见的坑、客户难缠场面——通用经验，按问题命中注入，见第八节 |
| 同上（问到产品怎么用时） | `general` | 说清八个入口分别干什么，并给可点的**预填链接**把人直接送到那一页，见第九节 |

**它不做计算。** 这是整个接入里最重要的一条设计约束，理由见下。

`general` 模式有一条额外硬规则：**手上没有这票的数，就不许给数**。用户问"我这票要交多少税"，正确答案是"这数我给不了，你得去那票的报告页问"，而不是拿一个行业比例凑一个像样的数字。实测回答见第六节。

## 二、三条红线（写进 system prompt，靠代码层再兜一层）

### 1. 不许算数

上下文里灌的不是原始 JSON，而是**已经算好并格式化过的事实清单**（`factBlock()` 生成）。
金额一律 `70,862.40` 这种带千分位的字符串，AI 只能照抄。

为什么这么严：这个产品的全部价值是"数能拿去跟货代对账"。模型只要自己算错一次，而且算得还挺像，
用户就会开始怀疑每一个数——包括那些本来正确的。**宁可它不会算，也不能让它算。**

如果用户问"赚不赚"，它的正确反应是"真实成本是成本侧的数，你的卖价报告里没有，这个我不替你填"。

### 2. 不许给合计

`landedCost` 与 `cashRequired` 永不相加，这是产品铁律。prompt 里明确禁止"总计/一共/合计/整体成本"，
并要求用户硬要一个数时解释为什么不能加（可退增值税和 AD 保证金都是先交后退，加起来既不是成本也不是现金）。

### 3. 不许把待核说成已确认

`UF-01` 这类 232 归类的待核项，只能说"按不计入 232 这个口径算出来是 70,862.40"，
不能说"就是 70,862.40"。同时必须给出分支值（64,535.40）和最坏值（77,189.40）。

另外 prompt 里禁掉了「包税」「保证清关」「一定能进」「最终税费以此为准」——PRD §2.6 的红线。

## 三、技术接入

### 走 WorkBuddy 云服务的免密钥 LLM

- 应用：`通途计税`（`wbapp_xzALIWOaSl9ZyFGLoP0YE0`）
- 端点：`https://clearpath-duty.app.workbuddy.host`
- 前端通过 CDN 加载 `@tencent-ai/workbuddy-cloud-sdk@dev`，用 `publishableKey` 直连
- **不经过本项目服务端**：模型密钥不在代码里，也不需要一个 BFF 转发层

本地 `127.0.0.1:4173` 已实测可用（Origin 校验对本地开发放行）。

### 模型选择

优先 `deepseek-v4.1-flash`，回退 `glm-5.3` → `hunyuan-chat` → 列表第一个非 disabled 的模型。
不在代码里写死"某个模型一定存在"，模型列表为空时显式提示，不静默降级。

改模型只需改 `assistant.js` 顶部的 `CFG.modelPref`。

### 两种调用形态

| 页面 | 形态 | 理由 |
| --- | --- | --- |
| 报告页 | 流式（`stream: true`，逐字渲染） | 问答要看"它正在想"，且可中途停止 |
| 录入页 | 流式收集 + `response_format: json_object` | 要结构化回填，一次性拿到 JSON 再解析 |

录入页在解析失败时不猜：返回"我没听明白这句，换个说法再试一次？比如……"，
而不是硬塞一个错的国家或货值。

### 上下文规模

一票美国报告的 system prompt 约 2.7 KB（含完整事实清单）。控制在 3 KB 以内，
足够精炼，也让首 token 更快。

## 四、失败与降级（不联网也能用）

| 情况 | 表现 |
| --- | --- |
| CDN 脚本加载失败 / 断网 | 提示"连不上 AI"，并展示 5 条**不用联网也能答**的常见问题（双口径区别、为什么没有合计、待核项是什么、能不能直接报关、HS 怎么定） |
| 未授权（访问地址不是发布域名） | 同上，换一句提示 |
| 额度用完 | 明确说"额度用完了"，不做无限重试 |
| 模型服务抖动 | 提示稍后再问，保留已渲染的文字，不整段清空 |
| 用户点停止 | 保留已生成的内容并写入历史，不丢弃 |

这满足了项目约束里"外部调用必须有未配置则降级"的要求——**AI 挂了，产品仍然是个能算的工具**，
不会变成一个白屏。

---

## 五、额度保护

前端限流：同一会话 60 秒内最多 6 次提问，超出直接提示。
历史只存 `sessionStorage`，单条截断 3000 字、最多 16 条，刷新还在、关掉就清。

## 六、实测结果

| 用例 | 结果 |
| --- | --- |
| 报告页问"这单赚不赚？真实成本和要备现金差在哪" | 427 帧流式、667 字，正确引用 70,862.40 / 64,535.40 / 77,189.40 / 6,327.00，正确说明两口径为何恰好相同（本票国内税 0.00、无可退），并主动点出"232 是跳过不是不用交" |
| 录入页输入"500 台铝制散热器发到布达佩斯，FOB 4.8 万美金，海运费 3200，卖给当地公司" | 回填 目的国 HU / 货值 48000 / 运费 3200 / 数量 500 / 渠道 B2B，**HS 编码故意留空**并提示"建议让货代或报关行复核后再定" |
| 浏览器控制台 | 0 报错 |
| 回归 | 黄金用例 38/38、文案门禁 15 段 0 命中、性能 p95 未退化 |

一个值得记录的 bug：首次联调时点悬浮球会预热一次、点问题又会预热一次，
第二次预热结束时的 `setStatus('idle')` 把正在生成的状态覆盖成空闲，导致"停止"按钮闪掉、
外部误判为流已结束。修法是给预热加 Promise 去重锁，并让 `setStatus` 在生成中拒绝被非 `busy` 状态改写。

另一个更隐蔽的：预览框 `.ta-preview` 加了 `display: flex`，把 `[hidden]` 的浏览器默认样式盖掉了，
于是**每次打开面板都先空着一个破图框**（图片元素没 src）。肉眼扫一眼很容易当成"还没加载完"放过去。
修法是补一条 `.ta-preview[hidden] { display: none; }`，并在 E2E 里钉住"没选图时不显示空预览框"。
凡是给可能带 `hidden` 的元素写 `display`，都要顺手补 `[hidden]` 那条。

## 七、看图填表（单据识别）

客户手里最多的不是文字，是发票、装箱单、报关单、询价邮件截图。所以录入页支持直接发图，
助手把图上的数读出来填进表单。

### 为什么不是"一个模型读一遍就填"

做过实验，结论很硬：**图片稍微糊一点，模型会同等地"自信"，给出一个不存在的数字。**

同一张发票，`48,000.00` 印得小，两个模型分别读成 `80,000` 和 `8,000`；两张清晰度不同的图，
连国家编码都能读出两个答案。模型说"读到了"和图上确实印着，是两件完全不同的事。

对计税产品这是致命的——货值错一位，整份报告全错，而用户看到的是"AI 帮我填好了"。

所以这里不是"AI 填表"，是**两家模型交叉取证 + 机器验引文**：

| 关 | 做什么 | 不这么做会怎样 |
| --- | --- | --- |
| ① 双模型独立读 | `deepseek-v4.1-flash` 与 `glm-5v-turbo` 各读一次，互不可见；**第二家必须避开第一家实际用上的那个**（第一家降级到备选时尤其要剔掉） | 单模型读错没人拦；更糟的是两家是同一个模型，一致是假的，给了用户不该有的确信 |
| ② 逐个字段比 | 两边都有且一致才算读到；只有一边有 → 不填，交给用户点 | 替用户决定一个可能是错的 |
| ③ 引文核对 | 每个要填的字段，必须附上图上那句原话，且**数值必须能在原话里找到**（`8708.91` 要能在引文里逐位找到） | 模型改写原文或凭空生成时无法识别 |
| ④ 常识校验 | 运费 > 货值、数量为 0、日期在未来十年外，一律摘掉 | 明显不合理的值流进引擎 |
| ⑤ 写进表单 | 真的写进 DOM，再回读确认；写不进去就如实说"有 N 项没找到输入框" | 面板说填了、表单其实是空的 |

第 ③ 关是整套的核心。**"读到了"不算数，"图上那句话撑得住"才算数。**

### 三条硬规则

1. **宁可不填，不可填错**。看不清就进 `missing`，表单留空，用户自己补。空着只是麻烦，填错是事故。
2. **一票多品名不替用户合**。一张发票两行不同 HS 编码（8708.91 散热器 + 8708.99 支架），
   编码和数量一律不填——合起来算的是一个不存在的品名，税率会用错。总货值照填，并在面板上说明
   "这张单有 2 行、2 个 HS 编码"，给出"去批量试算"的出口。
3. **同一编码多行不算多品名**。8708.91 分两批装运是正常的，照填。

### 成本与降级

- 三个入口：面板里的「单据」按钮、在输入框里 **Ctrl+V 粘贴截图**、把图片拖到面板上。
  截图粘贴是最常用的，E2E 里单独验过。
- 一张图 = **两次**模型调用（两家各一次），额度按 2 次记。限流里直接扣 2。
- 第二家挂了 / 额度不够 → 退化成单模型，且只填引文能核实的那些，面板注明"这次只有一个模型能用上，所以我把关得紧一些"。
- 两家都看不了图 → 明说"眼下能用的几个模型都看不了图"，并给出纯文字输入的替代路径。
- 前端先用 `canvas` 压到长边 1600、JPEG 0.82 再上传。实测 3000px 原图 1.2 MB → 180 KB，
  识别效果不降反升（图太大模型反而糊）。

### 实测结果

| 场景 | 结果 |
| --- | --- |
| 首页问"我这票发美国的汽配，要交多少税？" | 开头第一句就是"这数我给不了——我手上没有你这票的任何数据，凭空说个数就是编"，然后分两条路把人带到「新预演」和「历史报告」，最后补一句通用的 HS 归类 / 原产地提醒。**没有凑任何数字。** |
| 单品名发票（8408 → 8708.91 / 500 PCS / 48,000 / 3,200 / 2026-10-20） | 六项全填，每项都带图上原话，`hsCode` 从 `8708.91` 规范成 `870891` |
| 多品名发票（两行 8708.91 + 8708.99） | 填了目的国/总货值/运费/申报日共 4 项；编码与数量留空并给出拆票提示 |
| 一张生活照（马克杯 + 书） | 认得出"不是外贸单据"，表单**一个字符都没改** |
| 模糊图（字太小的压缩样张） | 两家读数分歧 → 全部进待确认，不自动填 |
| Ctrl+V 粘贴截图 | 能出预览，与点「单据」选文件等效 |

三个场景已固化成 E2E：`node scripts/e2e-doc-all.js`（真浏览器 + 真模型，约 1-3 分钟）。
清洗逻辑本身有 28 项单测（`tests/doc-intake.test.js`），用的 fixture 是**真实捕获的模型输出**，
不是手编的理想数据——包括那张把 48,000 读成 80,000 的。

## 八、外贸常识包（2026-10-25 新增）

### 为什么不是直接搬一个专家 skill

需求原话是"把外贸业务经理那个专家的 skill 直接搬过来"。搬不了，四个理由：

1. **形态不兼容**：专家 skill 跑在宿主里，能读文件、跑脚本、调 Office；老周是浏览器里一段 JS，只收发文本。skill 里凡是"读参考文档""执行校验脚本"的部分，搬过来是死代码。
2. **体积对不上**：专家包 250KB–33MB。一票报告的 system prompt 只有 2.7KB，专门压在 3KB 内换首 token 速度。
3. **会破红线（最关键）**：这类 skill 必然含报价核算、成本构成、佣金利润的方法论。搬进来等于给老周发了算盘，它会开始答"这单大概能赚多少"，双口径体系当场失效。
4. **授权**：专家包带 LICENSE，是市场分发的授权内容，不能整段复制进另一个产品。

所以只取**判断和话术**，不取**指令和计算**。代码在 `public/js/trade-knowledge.js`。

### 九类主题

| id | 讲什么 | 典型触发问法 |
| --- | --- | --- |
| `flow` | 询盘→报价→PI→收定金→生产验货→订舱→报关→收尾款 | "这单接下来该干什么" |
| `quote` | 报价单必含项、最容易漏的两项 | "报价单要写什么" |
| `payment` | 按睡得着程度排：预付→定金加提单副本→LC→D/P→赊销 | "付款方式怎么定" |
| `docs` | 三处必须一模一样、指定货代的提单风险 | "单证对不上怎么办" |
| `lc` | 软条款三种典型写法 | "信用证能不能接" |
| `incoterms` | 谁付运费/谁买保险/风险在哪转，重点讲 DDP | "客户要 DDP" |
| `risk` | 六种"风险全在你这边"的单子 | "这单该不该接" |
| `talk` | 砍价、催款、延误、要账期怎么说 | "客户一直压价" |
| `origin` | CO / FORM E / 普惠制 / RCEP 各自的用途 | "原产地证能省多少" |

### 按命中注入，不是全塞

`generalSystemPrompt(question, activeIds)` 先做关键词匹配（长词权重更高），
命中最多两条拼进 system prompt；**一个都没命中就原样返回 `GENERAL_SYSTEM_PROMPT`，一个字节不涨**。

实测：基线 893 字 → 命中 DDP 问题后 1,488 字（+595 字，约 1.2KB）。

指代继承：本轮没命中、但问句 ≤14 字（"那这个具体怎么弄"），带上轮的最后一个主题。
长问句不继承——"你们这个工具的报告怎么看"带着"贸易术语"跑，会把话带偏。

### 三条自我约束（`tests/trade-knowledge.test.js` 11 项钉着）

1. **正文不许出现阿拉伯数字、货币、百分比费率**——出现就会拿它去套这票的账
2. **不许出现内部字段名与禁用词**（`landedCost` / 包税 / 保证清关 / 总计…）
3. **每条 ≤420 字**——按命中注入，太长拖慢首 token

注入块自己还带一句刹车：「下面是通用的行内经验，不是这票的数，不要据此推算这票能赚多少」。

### 实测

问「客户要 DDP 到门，这单我该不该接」，回答 474 字，要点：

> 能接的前提——你或者你的货代在目的国有进口资质……这三条有一条不成立，就别硬接。
> 先把目的国的落地成本算一遍，算得通再接，算不通就改 DAP，让客户自己清关。
> 至于这票到底要交多少税、落地成本多少，我手上没你的数，说不了。你去「新预演」把这票填进去。

给了实质判断和可执行动作，同时**没有越过边界**：不报数、不承诺、把该算的活推回引擎。

手动复跑：`node scripts/e2e-kb-live.js "你的问题"`（消耗一次额度，不进 verify 基线）。
机制回归：`node scripts/e2e-trade-knowledge.js`（10 项，不调模型）。

## 九、能力迁移地图（2026-10-25）

需求是"把 AI 助手的能力都迁移到产品客服上"。先说结论：**能做的是把"结果"迁过去，不是把"工具"迁过去。**

### 迁了什么

| 原来的能力 | 老周现在怎么用 | 落点 |
| --- | --- | --- |
| 知道这个产品长什么样 | 功能地图 8 个入口：新预演、批量、历史、日历、待核、准确率、报告 15 段、工具边界 | `product-map.js` |
| 知道参数库覆盖哪些市场 | 进页面时拉 `/api/meta/countries` 和 `/api/meta/hs`，问到才注入 | `coverageBlock()` |
| 会指路、能带人直达 | 回答里给 `/quote/new?country=VN&...` 这种预填链接，前端渲染成胶囊按钮 | `ROUTE_RULES` + `renderText()` |
| 外贸行内经验 | 9 类常识（流程/报价/付款/单据/信用证/术语/风险/话术/原产地） | `trade-knowledge.js` |
| 多轮上下文 | 16 条历史 + 外贸主题继承 | `assistant.js` |

实测两例：

- 问「我手上有一百多票要一起算」→ 直接给「批量试算」的链接，说清必填六列，并补一句"一票多品名的要拆行"。
- 问「能算越南和泰国的光伏组件吗」→ "能，越南 VN、泰国 TH 都在清单里，光伏电池组件已入库"，同时拒绝给金额，把人推向新预演。

### 没迁，而且建议永远别迁

**1. 不在聊天窗口里直接出数。**
技术上做得到（前端调 `/api/quote/precheck` 就行），但做了就把产品最值钱的部分扔掉了：聊天里蹦出来一个数字，用户拿不到确认页的归类、拿不到 15 段报告里的待核项、拿不到双口径和最坏情况。一个没有出处的数，比没有数更危险。

所以"执行计算"这件事，老周的形态是**生成预填链接**——能确定的参数替你填好，不确定的（比如申报日）留空让你补，点进去走正式流程。

**2. 不给工具执行权（写文件、跑命令、跳转）。**
这些能力在宿主里是助力，在浏览器客服身上就是漏洞面。老周唯一被允许的动作是"给一个站内链接"，而且链接要过白名单。

**3. 不搬专家 skill 原文。**
理由见第八节开头那四条。一句话：这类 skill 必含报价核算方法论，搬进来老周会开始算钱。

### 三块知识按命中注入

`generalSystemPrompt(question, activeIds, coverage)`：

| 块 | 最多注入 | 典型触发 | 增量 |
| --- | --- | --- | --- |
| 外贸常识 | 2 条 | "客户要 DDP" | +595 字 |
| 功能地图 | 1 条 | "一百多票怎么算" | +315 字 |
| 覆盖范围 | 1 条 | "能算越南吗" | +642 字 |
| 都不命中 | 0 | "今天天气怎么样" | **0 字** |

基线 1,258 字（含常驻的指路规矩约 250 字），最坏三块同时命中 2,768 字（约 8KB）。
测试用**绝对上限 3,000 字**卡，不用"基线的两倍"——基线会随功能扩张往上走，倍数上限跟着漂，最后就变成永远都过得去。

### 链接白名单为什么必须存在

`esc()` 只处理 `& < > " '`，对 `href="javascript:alert(1)"` 和 `href="//evil.com"` 完全无效。所以 `product-map.js` 里的 `isSafeChatLink()` 把路径和参数按字符集卡死：

- 放行：`/quote/new`、`/quote/batch`、`/reports`、`/calendar`、`/demo/*`、`/quote/<id>/report`，参数只许 `A-Za-z0-9%._~=&;+-`
- 拦掉：`//evil.com`（协议相对）、`javascript:` / `JavaScript:`、`/admin/*`、`/quote/../../etc/passwd`、带 `#` 或 `<` 的

规则和校验放在同一个文件里——分开写迟早漂移。测试里有一项专门验证"规矩里给的示例链接自己得先过白名单"。

### 验证

- `tests/product-map.test.js` 11 项：入口完整性、红线、参数名拼写、示例链接过白名单、14 种恶意路径、命中率、单条上限、路径必须真实存在
- `scripts/e2e-assistant-route.js` 12 项：真浏览器 + 真模型，验证链接渲染成 `ta-go` 且只有 1 个、没有外站
- 基线：167 通过 / 0 失败 / 文案门禁 0 命中 / p95 0.57ms
