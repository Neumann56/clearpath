# 通途小程序 · 架构设计

> 目标：**能被人真的用起来，而不是只能在自己电脑上跑。**
> 这份文档只写决策和理由，接口细节看 `API.md`，导入步骤看 `MINIPROGRAM.md`。

---

## 0. 一句话结论

小程序端**不做任何计算**，只做三件事：把一句话读成表单、把服务端算好的数排好、把"算不准的地方"如实摆出来。

算数只有一份实现（`lib/engine/`），PC / H5 / 小程序三种壳共用。这条守住，才不会出现「手机上显示 5.2 万，电脑上显示 5.1 万，用户不知道该信哪个」。

## 1. 三档通道（这是整个设计的关键）

微信对小程序**自己发起**的网络请求有硬约束：只能打 https、已 ICP 备案、且在小程序后台配置过「request 合法域名」的地址。

通途现在的后端是 `http://47.123.4.136:8080`——**正式版一个请求都发不出去**。这不是配置问题，是规则问题。

所以请求层做了三档，`config.js` 里改一个字母切换：

| MODE | 链路 | 备案要求 | 什么时候用 |
|---|---|---|---|
| `direct` | 小程序 → 后端 REST | **必须** https + 备案域名 | 开发者工具开发、已备案后 |
| `proxy` | 小程序 → 云函数 → 后端 | **不需要** | 想让陌生用户真的用上 |
| `mock` | 小程序 → 本地样例数据 | 无 | 断网演示、评委面前兜底 |

**为什么 `proxy` 能绕过备案**：那条白名单只约束小程序端自己发的请求。小程序调 `wx.cloud.callFunction` 走的是云开发通道，不受域名白名单约束；云函数在服务端再去请求后端，属于普通服务端出网，不看 https 也不看备案。

代价要说清楚，不能只讲好处：

- 多一跳，国内实测 +60~150ms
- 云函数调用按次计费（免费额度对比赛和早期用户够用）
- 云函数默认超时 **3 秒**，必须去控制台改到 60 秒，否则老周一定超时——这条不写下来，第一次部署必然踩
- `callFunction` 是一问一答，**没有 SSE 通道**。所以 `/proxy` 档下老周不是打字机效果，是"停顿一下，整段出现"。这是真实限制，界面不假装有流式

## 2. 分层

```
┌──────────────────────────────────────────────┐
│  pages/          7 页 · tabBar 5             │  只管这一屏怎么显示
│  components/     3 个复用组件                │  只管一类东西怎么长得一致
├──────────────────────────────────────────────┤
│  utils/                                      │
│    api.js     请求层（唯一出口）              │  ← 换通道只改这里
│    llm.js     老周的对话通道（流式/整段）      │
│    store.js   覆盖数字缓存 · 参数版本 · 最近一票│
│    fmt.js     纯格式化，不含任何计算           │
│    share.js   分享文案（合规约束写在这）        │
│    persona.js 老周人格 + 五条红线              │
│    demo.js    离线样例单                      │
├──────────────────────────────────────────────┤
│  cloudfunctions/apiProxy/   免备案转发 + LLM  │  唯一对外开放的入口
├──────────────────────────────────────────────┤
│  后端（Node，零依赖）  /api/*  ← 算数只在这里   │
└──────────────────────────────────────────────┘
```

**分层不靠自觉，靠三条硬规矩：**

1. 页面里**不许**出现 `wx.request`。所有网络请求走 `utils/api.js`。
2. 页面里**不许**出现后端地址。全包只有 `config.js` 一处写死（测试脚本会扫，出现在别处就失败）。
3. 页面里**不许**做算术。`fmt.js` 只格式化和加千分位，一个 `+` 都不许有。

## 4. 六个设计决策

### 4.1 双口径做成组件，且**不提供合计属性**

真实成本（`landedCost`）算毛利，需备现金（`cashRequired`）算现金流。两个数并排放，人很容易手一滑写个 `total`——加上去还挺"合理"，因为看起来都是钱。

所以从组件契约上就不给这条路：`amount-dual` 只有 `landed` / `cash` / `gap` 三个数值属性，**没有任何合计字段可传**。想加也加不了。测试里有一条钉着"组件不许出现 total/sum/合计 类属性"。

> 反过来做会怎样：做一张大的"总成本"卡，把两个数加起来。数字很好看，但业务上它什么都不是，报出去的价格会错。

### 4.2 手机端是独立模板，不是给 PC 加媒体查询

PC 先摆表格再给结论；手机反过来，**先给两个数，明细全部折叠**。序号顺序也不同（手机上"钱怎么算的"必须排第一，因为那是唯一能让人相信这两个数的地方）。

### 4.3 跨页交接走 storage，不走 URL

`wx.switchTab` **不能带 query**。带了不报错，参数就是没了。所以首页"一句话录入"的结果放 `tt_draft`，由「预演」tab 的 `onShow` 取走消费。

> 这个坑很难查：日志一切正常，只是数据永远空。第一次遇到会以为是解析失败。

### 4.4 设备号必须随每个请求带

报告按设备隔离。小程序没有浏览器那种 cookie 自动往返，所以自己生成 `tt_did` 持久化，通过 `x-device-id` 头传。

**幂等键必须带设备号**：`fingerprint@paramsVersion@did`。少这一段，两个不同的人提交同样的输入，会拿到同一份报告——第二个人在自己的历史里看不到它，第一个人的报告却被别人的数据覆盖。这个 bug 在 PC 版真实发生过一次。

### 4.5 错误分三层，各层说各层的话

| 层 | 例子 | 界面怎么说 |
|---|---|---|
| 网络层 `net` | 域名没配、断网、服务没起 | 说清楚**怎么修**："检查 config.js，以及有没有勾『不校验合法域名』" |
| 业务层 `biz` | 400 缺申报日、409 参数挂起 | 服务端原话照登，**不许**统一改成"计算失败" |
| 通道层 `mode` | 云开发没开通、envId 没填 | 说清楚缺哪一样、去哪儿补 |

> 通用兜底文案会把"能解决的问题"伪装成"故障"。凡是 `catch` 里写死一句话的地方，先问它有没有把原因吃掉。

### 4.6 `wx:for` 一律带 `wx:key`，且 key 用序号不用名称

同一份报告里出现两条「关税」很正常（不同税目）。用名称当 key 会撞，撞了**不报错**，只是列表更新时按位置复用节点，出现"A 行显示 B 的数"这种最难查的错位。所以 `report.js` 的 `buildView()` 给每一行补 `i`，模板一律 `wx:key="i"`。

## 5. 一条数据怎么流过去

以「一句话录入」为例：

```
用户输入 → POST /api/parse（云函数转发或直连）
        → 得到 draft{country, hsCode, fob, freight, qty}
        → 写 storage: tt_draft
        → switchTab('pages/new/new')
                
new 页 onShow → 读 tt_draft → 消费并删除
             → 等国家列表就绪才能算国家下标（没就绪先挂起）
             → applyDraft() → estimate()
             
estimate()  → 420ms 去抖 → POST /api/quote/precheck
            → 只用来"边填边看"，失败不打断录入

提交       → POST /api/quote → 得到 reportId
          → navigateTo('pages/report/report?id=...')
          
报告页      → GET /api/report/:id → buildView() 整形成 wxml 能铺开的纯对象
```

`buildView()` 只做整形，不做计算。wxml 里不能调函数、不能做复杂判断，所有格式化必须在 JS 里做完——好处是模板里全是 `{{}}`，一眼能看出哪块对应哪个数。

## 6. 增长设计（不碰红线）

分享是小程序唯一免费的获客入口，但微信对**诱导分享**处罚很重：轻则限制分享能力，重则封禁。所以：

- ❌ 分享解锁、拉人砍价、集赞、助力 —— 一律不做
- ✅ 分享标题只陈述事实：「匈牙利 8708.91：真实成本 52,134.48，报关要押 66,210.79」
- ✅ 落地页是首页，**不是那份报告**

最后这条反直觉，但必须这样：

> 报告按设备隔离。分享里带 `reportId`，朋友点进来设备号不同，只会看到一个打不开的空白页。看起来牺牲了转化，实际是唯一不会当场翻车的做法。

其他获客动作：

| 动作 | 说明 | 状态 |
|---|---|---|
| 朋友圈分享 | 5 个 tab 页都能分享到朋友圈 | 已做 |
| 分享落地点提示 | 从分享进来时首页挂一条说明 | 已做 |
| 首屏样例 | 新用户没有历史，用一票标注清楚的样例顶着 | 已做 |
| 订阅消息（政策提醒） | 申报日临近时推一条 | **未做**，需要模板 ID + 后端定时任务 |
| 搜一搜/小程序码 | 发布后在后台配置 | 上线后 |

## 7. 上线路径

三条路，按"多久能被陌生人用上"排：

### A. 云开发转发（最快，推荐）

| 步骤 | 耗时 | 卡点 |
|---|---|---|
| 开通云开发，拿环境 ID | 10 分钟 | 免费额度够早期 |
| 填 `CLOUD.envId`，`MODE = 'proxy'` | 1 分钟 | |
| 右键 `cloudfunctions/apiProxy` → 上传并部署 | 3 分钟 | 第一次要"云端安装依赖" |
| **控制台把超时从 3 秒改到 60 秒** | 1 分钟 | 不改老周必超时 |
| 上传代码 → 提交审核 | 1 天 | 见下面的审核要点 |

**全程不需要备案**。

### B. 备案域名 + https（稳，但慢）

买域名 → ICP 备案（**7–20 个工作日**）→ 配 https 证书 → 后端加 443 → 小程序后台配 request 合法域名 → `MODE = 'direct'`。

比赛期间基本来不及。

### C. 演示模式（立刻）

开发者工具勾「不校验合法域名」，`MODE = 'direct'` 直连 IP。**只在自己电脑和手机上有效**，给评委看可以用，给别人用不行。

## 8. 提交审核的三个坑

1. **主体与类目**。成本测算类建议「工具 > 效率」。企业主体才能选「商业服务」类目，个人主体不行。
2. **名称与简介不要出现"代理报关""清关服务"**。这类表述会被要求补《报关企业注册登记证书》。写「外贸到岸成本测算」就没事——我们本来也不代办任何手续。
3. **《小程序用户隐私保护指引》必须填**。好消息是通途**不上传任何个人信息**：设备号本地生成、只用于区分报告归属，不关联身份。隐私指引里据实勾"不收集"即可，省掉一堆合规工作。

## 9. 性能预算

| 指标 | 预算 | 现状 |
|---|---|---|
| 主包体积 | ≤ 2MB | **105KB**（云函数不计入主包） |
| 首屏可交互 | ≤ 1.5s | 覆盖数字有 30 分钟缓存，二次进页面直接读 |
| 页面切换 | ≤ 300ms | 无重计算，`setData` 只推变化字段 |
| 单个请求 | ≤ 400ms | 引擎 p95 0.62ms，瓶颈在网络 |

三个具体手段：

- `lazyCodeLoading: "requiredComponents"`：只加载当前页用到的组件
- 覆盖数字走 `store.js` 缓存（半小时），首页和录入页共用一份
- 大列表（视频 13 条、日历 22 项）一次性渲染，不做虚拟列表——数据量根本不值得

## 10. 明确不做的

写下来是为了防止下次有人"顺手加上"：

| 不做 | 原因 |
|---|---|
| 手机端批量试算 | 一次录 20 票在手机上没法操作，PC 版做 |
| 图片回填（拍单据读字段） | 实测 `48,000.00` 会被读成 `80,000`，错一个数整票作废 |
| 在聊天窗口直接出数 | 拿不到归类、15 段待核、双口径、最坏值——**没有出处的数比没有数更坏** |
| 分包 | 105KB 不需要 |
| 第三方状态库 | 为三个字段装一套框架不值 |
| 流式打字机（proxy 档） | `callFunction` 没有 SSE 通道，做不到就是做不到 |
