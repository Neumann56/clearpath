# 通途小程序 · 需求与边界

> 从 Web 版（7 个页面、15 段报告）搬到手机端，不是等比缩放。
> 手机屏幕装不下 15 段，装得下的是**三个判断**：这单要花多少、要备多少现金、哪些还没算准。

---

## 一、一句话定位

外贸业务员在客户催报价的 3 分钟内，掏出手机就能算清一票货的到岸成本，并看清哪几项自己还没把握。

**不是**报关工具，**不是**税费计算器。只做决策支持。

---

## 二、为什么值得单独做一个小程序

| Web 版的问题 | 手机端的机会 |
| --- | --- |
| 要开电脑、找网址、输地址 | 微信里点开就用，不装 App |
| 表格一行行填，人在外面填不了 | 一句话录入，或者拍发票让老周读 |
| 报告 15 段，手机上滚到怀疑人生 | 首屏只给两个数 + 三件事 |
| 开会时没法演示 | 扫码即开，讲完就能发给评委 |

比赛场景下最实际的一条：**评委的手机上没有你的网站，但都有微信。**

---

## 三、保留 / 砍掉

### 保留（这是产品本体，一样都不能少）

| 能力 | 为什么必须留 |
| --- | --- |
| **双口径**（真实成本 / 需备现金） | 整个产品的立命点，合成一个数等于产品作废 |
| **待核清单 + 影响金额** | 「这个未决事实值 6,327 美元」是唯一的差异点 |
| **税率出处与置信度** | 评委第一个问题就是「你这数哪来的」 |
| **最坏值区间** | 报价要按最坏报，不给区间等于没算 |
| **要办的事**（认证、许可、单证） | 手机端反而是优势：现场就能把待办拍照发同事 |
| **政策日历** | 决定「什么时候申报」，比算多少更常被问到 |
| **老周** | AI 是加分项，但必须守「不算数」的规矩 |

### 砍掉（搬过去也是摆设）

| 砍掉 | 理由 |
| --- | --- |
| 参数治理 / 草稿 / 发布审批 | 后台运维场景，手机上审不了 400 条参数 |
| 预演准确率校准 | 要上传实际清关单据，PC 上做才合理；手机端只给「去看」入口 |
| 批量试算（≤200 行） | 要传 CSV 文件，手机没有文件系统入口 |
| 打印页 | 手机不打印。改成「生成图片发微信」更实际（本期先给分享链接） |
| 待核项审批流转 | 需要操作人密钥，手机端不做 |

砍掉的都可以在「关于」页里写明「这些在电脑版」，说清楚比藏起来好。

## 四、页面结构

### tabBar 五个

```
首页      预演      历史      看懂      老周
```

非 tab 页面：报告详情、政策日历、边界说明。

### 1. 首页

- 品牌条：通途 / 报价前先把账算清
- **一句话输入**（大字，占首要位置）+ 三个示例胶囊
- 双口径说明卡（两数并列，明确写「永不相加」）
- 覆盖范围一行小字：`68 个市场 × 6 个品类`
- 三个入口：新预演（逐项填）/ 政策日历 / 看懂外贸

首屏不许出现任何需要滚动才能看到的按钮。

### 2. 预演（录入）

原有 7 个必填，手机上按「手指从哪来」重排：

| 顺序 | 字段 | 交互 |
| --- | --- | --- |
| 1 | 目的国 | 底部弹出，按 7 个区域分组，可搜 |
| 2 | HS 编码 / 品名 | 文本 + 品类快捷选，写品名也认 |
| 3 | FOB 货值 | 数字键盘 |
| 4 | 运费 | 数字键盘，默认 0 |
| 5 | 数量 | 数字键盘 |
| 6 | 渠道 | 分段控件 B2B / B2C（两态，不做下拉） |
| 7 | 申报日 | 日期选择，默认今天 |

高级项（保险、金属含量、反倾销、面积、摊销）全部折叠进「更多选项」，**默认不展开**，展开后逐项带一句为什么问。

底部固定一条：`预计：真实成本 ≈ -- 需备现金 ≈ --`（填够就实时出估算，不用等提交）。

### 3. 报告详情

分 5 组，默认只展开第 1 组：

| 组 | 内容 | 默认 |
| --- | --- | --- |
| ① 两个数 | 真实成本、需备现金、现金缺口比、状态标签 | 展开 |
| ② 钱是怎么算出来的 | CIF → 关税 → 增值税链 → 规费，逐行带税率和基数 | 收起 |
| ③ 还没算准的 | 待核清单，每项标影响金额；数据缺口 | 展开（这条不许收起） |
| ④ 要办的事 | 认证、许可、单证，带提前期 | 收起 |
| ⑤ 别的可能 | 最坏值、敏感度、时间线、假设 | 收起 |

**第 ③ 组默认展开，且空的时候要写「本票没有待核项」，不许直接不显示** —— 空白让人以为是没做。

### 4. 历史

列表卡片：日期 / 国家 / 编码 / 双口径两个数 / 状态色点。支持下拉刷新、触底加载。

### 5. 政策日历

按月分组时间轴。今天之后 30 天内的高亮。顶部一句：只收录已入库节点，没列出来不代表没变化。

### 6. 看懂外贸

三组视频，每组一条主课通栏。点开才加载播放器。

**小程序里 B 站播放器不能用 iframe**（没有 iframe，web-view 需要业务域名备案）。降级方案：
- 卡片显示封面、时长、作者、看完能答上什么
- 点击 → 复制原站链接 + 提示「在浏览器中打开」
- 这是真实限制，不假装能内嵌

### 7. 老周

- 全屏对话页，底部输入条
- 走服务端 `/.cloud/` 同源转发（绕开云服务 key 的 Origin 白名单）
- **微信小程序不支持 SSE 流式**，改一次性返回 + 前端打字机逐字显示，观感接近
- 三条硬规则照旧：不算数、不给合计、不说包税
- 支持「拍发票」入口 → 提示「图片识别在电脑版」

## 五、必须处理的三个技术约束

### 1. 域名白名单（最硬的拦路虎）

微信小程序正式版请求必须满足：**https + 已备案域名 + 在小程序后台配置 request 合法域名**。
`http://47.123.4.136:8080` 两个条件都不满足。

因此分三档：

| 档位 | 能否跑 | 怎么用 |
| --- | --- | --- |
| 微信开发者工具 + 勾「不校验合法域名」 | 能 | **比赛演示用这一档**，5 分钟就能跑起来 |
| 真机预览（同一局域网/公网 IP） | 不能 | 同上，必须开调试模式 |
| 正式发布 | 需要域名 + 备案 + 配置合法域名 | 要 7–20 个工作日，比赛前来不及 |

**结论：本期交付「能导入、能演示、能讲清限制」的代码包，不承诺正式发布。**

### 2. 断网兜底

比赛现场网络不可靠是常态。小程序内置一票样例报告（`mock/report.js`），
**连不上服务端时自动切演示模式**，页面顶部打一条黄条「演示数据，不是实时计算」。
宁可让人知道是演示数据，也不能白屏。

### 3. 无登录态

Web 版靠 cookie 里的设备号分报告。小程序用 `wx.login` 换 code 需要后端换 session，
本期简化为：请求头带 `X-Device-Id`（小程序本地生成存 storage），服务端 `ensureDevice` 已支持自定义设备号逻辑需补一条。

---

## 六、不做什么（写进「关于」页）

- 不做报关、不代缴税、不出正式单证
- 不给「包税」「保证清关」这类承诺
- 不在聊天窗口给最终金额（算法上做得到，但用户拿不到出处和待核清单）
- 不做多用户协作、不做权限体系
- 不做离线完整计算（离线只给样例）

---

## 七、验收标准

一条都不能少：

1. 首页不滚动就能看到输入框和「试算」按钮
2. 从输入一句话到看见两个数，**不超过 3 次点击**
3. 报告首屏必须同时出现：真实成本、需备现金、状态标签
4. 待核清单为空时，显示「本票没有待核项」而不是空白
5. 断网时能进入演示模式，黄条明确标注
6. 任何一个金额，点开都能看到出处或「未入库」说明
7. 手机宽度 375px 下，所有数字不折行、不截断
